# DBPoolSaturated — DB 接続プールが飽和に近い

**まず見る**: Grafana の昇格シグナルダッシュボード(プール使用率)。`db_pool_wait_total` が伸びていれば既に待ちが発生している。

**切り分け**
1. 全サービスで同時に高いか、1サービスだけか
   - 1サービスだけ → そのサービスの遅いクエリ(トレースで `sql.*` span の長いもの)かリクエスト増
   - 全部 → DB 側の劣化(フェイルオーバー・ストレージ)。RDS のイベントを見る
2. `MaxOpenConns`(既定25)に張り付いているだけか、DB の `max_connections` にも近いか
   (逆算式: MaxOpen × タスク数 × プロセス内接続数 < max_connections。internal-06 §10.5)

**対処**: 短期はタスク数を増やす前に**遅いクエリを止める**(プールはタスクを増やすと総接続が増えて DB 側に波及する)。恒久は逆算式の再計算 + 必要ならインスタンス分離。

**根拠**: 10.5(プール規約)。Go の既定は無制限で、これを入れた経緯は #215。
