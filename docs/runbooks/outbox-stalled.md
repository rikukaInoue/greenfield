# OutboxStalled — outbox の最古イベントが滞留

**まず見る**: relay プロセスが生きているか(ECS ならサービスのタスク数、ローカルなら relay の口グ)。
`relay: 排水して停止 unsent=N` が最後のログなら**止まったまま**。

**切り分け**
1. relay 停止 → 再起動すれば回復する(check #8 の性質。データは失われていない)
2. relay は生きているが送れない → relay ログの「送信に失敗」。バス側(SNS)の障害か、
   **キューポリシー等の認可**(7.3 で実測した「Publish は成功、配送だけ消える」は受信側で見える)
3. 追いつかない(送っているのに age が伸びる) → 流量に対して interval/batch が細い

**対処**: 1 は再起動。2 はバスの認可・到達性(検証ログ 2026-09-30-stage-73)。3 は RELAY_INTERVAL 短縮か Batch 拡大。再送は `photo republish --since`(inbox が重複を吸収する)。

**根拠**: check #8/#9、7.3 実測。
