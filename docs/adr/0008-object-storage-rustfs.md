# 0008. ローカルのオブジェクトストレージは RustFS（LocalStack S3 は使わない）

## 背景

題材をカメラ情報サイトにした時点で画像そのものの置き場所が必要になった。設計は署名付きURL方式
（アプリはバイト列を通さず、クライアントが直接ストレージへ PUT する）を採るため、
ローカル環境でも**署名の検証が本物と同じに働くこと**が前提になる。

SNS / SQS で使う予定の LocalStack には S3 も含まれるので最初はそれを使ったが、
署名なしのリクエストが通ってしまう。`S3_SKIP_SIGNATURE_VALIDATION=0` を設定しても変わらない。

同じ流れを RustFS（Rust 実装の S3 互換サーバ）でも測った。

| 検査 | 期待 | LocalStack | RustFS |
|---|---|---|---|
| 署名付き PUT | 200 | 200 | 200 |
| 署名付き GET | 200 | 200 | 200 |
| **署名なし PUT** | 403 | **200** | 403 |
| **署名なし GET** | 403 | **200** | 403 |
| 改ざんした署名で GET | 4xx | 403 | 400 |
| 不正なアクセスキー | 403 | 通る | 403 `InvalidAccessKeyId` |

## 決定

画像オブジェクトは **RustFS**（compose の `rustfs`、:9000）に置く。LocalStack は SNS / SQS 用として残す。

LocalStack は AWS のシミュレータであり、本物なら弾かれるものが通る。RustFS は S3 プロトコルの
実装そのものなので、署名検証・認証の失敗経路がローカルでそのまま再現される。
「ローカル実装は緩いより本物らしく厳しいに寄せる」という方針（`localauthz` と同じ）の適用。

バケットの作成は `dev/s3admin ensure-buckets`（`mise run s3:up` が呼ぶ）で行う。
DB の database 作成と同じくインフラ側の操作であり、サービスのマイグレーションには入れない。

## 影響

- ローカルのコンテナが1つ増える。RustFS のイメージは 357MB（LocalStack は 1.76GB）
- Phase 7（AWS）では endpoint と資格情報を差し替えるだけで実 S3 に向く。`blobstore.Config` の
  `Endpoint` が空なら本物の AWS を使う
- RustFS は比較的新しい実装なので、挙動差分に当たったら記録して Phase 7 の実機確認に回す

## 還流

プロダクション版のローカル環境で S3 を模擬する場合、LocalStack S3 は署名付きURLの検証に使えない。
署名を前提とする設計（アップロード・ダウンロードを直接ストレージに向ける形）を採るなら、
S3 互換の実サーバ（RustFS / MinIO 等）をローカルに置く必要がある。
