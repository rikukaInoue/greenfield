# 0007. 実装前に切った契約のバージョンは 1.0.0 にしない

## 背景

0.4 で各エンドポイントの契約（OpenAPI）を先に確定させ、`info.version` を `1.0.0` としてコミットした。
この時点でハンドラは全て `501 not_implemented` を返す骨格である。

1.1〜1.3 で実装を入れる際、`POST /photos` の成功応答を 200 から 201 へ変えたところ、
`mise run api:breaking` が破壊的変更として検出した。

```
error [response-success-status-removed] in API POST /photos
      removed the success response with the status `200`
```

ゲートは正しく動いている。`1.0.0` は「この契約は安定している」という宣言であり、
実装が入る前の骨格に対してそれを宣言したのが誤りだった。

## 決定

1. 200 のままにする。201 への変更は `/v2` の並行提供と合わせて 2.2 で行い、
   チェック #16 の完成形（破壊的変更 → メジャー更新 → 並行提供）の題材にする
2. 今後、実装が入っていない契約は `0.x` で切る。`1.0.0` は最初の実装が入った時点で付ける

## 影響

`POST /photos` は 200 を返す。RESTful には 201 が望ましいが、契約の互換性を優先した。

## 還流

`conventions/api-design.md` §3.4 に「実装前の契約は 0.x で切る」を追記する。
スペックを先に確定させる運用（huma の型からの生成）と、メジャーバージョン連動のゲートを
同時に採ると、骨格から実装へ移る段階で必ずこの問題が起きる。
