# 0004. 擬似ReBAC のタプルはサービスDBと別に置く

## 背景

`core/authz/localauthz` は OpenFGA + authzサービス（Phase 3.2）の差し替え前に使うローカル実装である。
タプルの置き場所として、サービスの DB（`photo`）に相乗りさせる案があった。

しかし本番の authzサービスは別システムであり、サービスのトランザクションには参加しない。
相乗りさせると `Atomic.Do` のロールバックでタプルも消えてしまい、本番と挙動が変わる。
検証チェック #6（孤児タプルは無害）は「タプルは書けたが業務側がコミットに失敗した」状態を作る実験なので、
相乗りでは再現できない。

## 決定

専用の database（`localauthz`）と専用ユーザーを立て、別の `*sql.DB` で接続する。
テーブル定義は `deploy/compose/mysql/init/` に置く（DBレベルの操作なのでサービスのマイグレーションには入れない）。

driver は合成ルート（`app/`）が注入するため、実装コードは `database/sql` にしか依存しない。

**訂正（監査 C-5）**: 「`core` は `database/sql` にしか依存しない」と書いたが、`core/go.mod` の
direct require には `go-sql-driver/mysql` が入っている（`localauthz_test.go` がローカルの mysql へ
接続して検証するため）。**実装は driver を知らないが、モジュールの依存には現れる**。
テスト専用依存を core に置いてよい条件と判別方法は ADR 0019 に定めた。

## 影響

- ローカル環境に database が1つ増える。Phase 3.2 で OpenFGA に置き換わって消える
- 業務トランザクションの中で `WriteRelations` を呼んでも、そのロールバックはタプルに及ばない（本番と同じ）

## 還流

なし（検証ビルド固有の実装）。
