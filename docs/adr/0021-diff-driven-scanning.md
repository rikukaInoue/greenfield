# ADR 0021: 継続的検査は差分運用にする

日付: 2026-09-30
状態: 採用
関連: #191 / #194、監査 A-1（fail-open にしない）、ADR 0017（api:breaking の差分比較）

## 文脈

継続的脆弱性検査（#180〜#192）は道具を何本入れるかより、**続くかどうか**で価値が決まる。
検査は毎回同じ結果を出す——ZAP は同じ alert を同じ数、Trivy は同じ CVE を同じ数。
人間は3回目から見なくなり、その瞬間からその CI ジョブは緑でも赤でも意味の無い飾りになる。

`api:breaking` は最初からこの形（base に対する差分だけを見る）で入れてあり、
**既知の状態との差分を見る**という考え方を検査全般に広げる。

## 決定

1. **基準（baseline）を固定し、新規に出たものだけを失敗にする。**
   共通機構は `dev/scripts/baseline-diff.sh`（検査側は検出を1行1件に正規化して流し込むだけ）。
   機構自身の挙動は `baseline-diff.test.sh` が固定する（`mise run baseline:test`、check に含む）。
2. **除外の書式を統一する**: 1行1件、`<検出キー>  # 理由 exp:YYYY-MM-DD #issue`。
   - 理由の無い除外は受け付けない（半年後に誰も外せなくなり、baseline は永久に膨らむ）
   - 期限の無い除外は受け付けない。**期限切れは失敗** = 放置の検出
   - 道具が自前の書式を持つ場合（Trivy の `exp:` 等）はそちらに従い、無い道具
     （ZAP の rules.tsv 等）はコメントで同じ情報を書く
3. **新規0件なら静かに緑。** 新規が出たときだけ落ちて目に入る。
4. **fail-open にしない**（監査 A-1 と同じ）:
   - baseline ファイルが無い → 失敗（空ファイルをコミットして始める）
   - 検出0件なのに baseline に件がある → 検査の空振りとして失敗
   - 各検査は「比較した件数」を出力する（空の結果と成功を区別できない書き方をしない）
5. 解消済み（baseline にあるが検出されなくなったもの）は**警告**で掃除を促す。
   失敗にしないのは、検出が揺れる検査（DAST）で偽の赤を作らないため。

## baseline の置き場

| 検査 | baseline | 書式 |
|---|---|---|
| Trivy（#187） | `.trivyignore` | 道具ネイティブ（`exp:` あり）+ 理由コメント |
| osv-scanner（#183） | `.osv-scanner.toml` | 道具ネイティブ + 理由コメント |
| ZAP（#189/#190） | `.zap/rules.tsv` | 道具ネイティブ（期限なし）+ コメントで `exp:` |
| gosec / golangci（#188） | `.golangci.yml` + inline `//nolint:xxx // 理由` | inline は理由必須（lint が強制） |
| その他（正規化できる検査全般） | `dev/baselines/<検査名>.txt` | 統一書式（baseline-diff.sh が検品） |

govulncheck（#180）と自前テスト（#182/#186）はノイズがほぼゼロなので baseline を持たず、
検出 = 即失敗のまま運用する。差分運用は「ノイズのある検査を飼う」ための機構であって、
ノイズの無い検査まで緩める理由にはしない。

## 却下した代替

- **各検査の道具ごとの suppress 機能だけで運用**: 書式も期限の扱いもばらばらになり、
  「期限切れの検出」を横断で回せない。道具ネイティブの suppress は使いつつ、
  規律（理由・期限・空振り検出）は共通機構と検品で揃える。
- **最後にまとめて差分運用化**: 2本目の検査が入った時点で既に誰も見ていない状態になる。
  仕組みを先に作り、#183 以降は入れる時点でこの形に揃える（本 ADR が根拠）。
