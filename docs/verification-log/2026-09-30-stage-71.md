## 2026-09-30 — [7.1] Terraform 最小構成: apply → 検証 → destroy（#62）

環境: ap-northeast-1、Terraform 1.5.7 / AWS provider 6.x。state はローカル（使い捨て）。
予算: Phase 7 全体で上限 $15 を宣言してから着手（この構成の実測ランレートは
ALB $0.0243/h + Fargate 256/512 $0.013/h + db.t4g.micro $0.016/h ≈ **$0.06/h**）。

## 構成（infra/main.tf）

単一 VPC + パブリックサブネット×2 + ALB + ECS Fargate(photo×1, ARM64) + RDS MySQL 8.4 + S3。

- **NAT Gateway を置かない**（$0.062/h + 転送の節約）。タスクはパブリックサブネットで
  public IP を持ち、到達制御は SG（photo:8080 は ALB SG からのみ、DB:3306 は app SG からのみ）
- **RDS は publicly_accessible = false**。最初は手元からのブートストラップ用に
  公開を試みたが、非公開に戻し、初期化も migrate も **VPC 内の one-off ECS タスク**に
  寄せた（migrate は本番も ECS タスクで流す形なので、その形の予行になる）
- ECR は同じ tf 内。`-target` で先に作って push → 全体 apply の2段

## 気づき

1. **RDS の「パブリックサブネットに居る」と「公開されている」は別**。
   `publicly_accessible` が無いと外から届かない。今回は公開せず、
   ブートストラップを VPC 内タスクに寄せる方が形として正しかった
2. one-off タスクへの SQL の運び方: イメージを焼かず `command` override に
   base64 で渡すと、使い捨て構成にビルドパイプラインを増やさずに済む
3. Fargate の `exitCode` を待って判定する形（`aws ecs wait tasks-stopped` →
   `describe-tasks`）で、migrate の成否が機械判定できる
