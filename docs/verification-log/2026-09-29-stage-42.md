## 2026-09-29 — [4.2] Eventual: outbox + relay + SNS/SQS FIFO + inbox（#52 / check #8・#9）

### 作ったもの

  - `Outbox.Publish` — ctx から tx を取れなければ `ErrPublishOutsideTx`。
    **規約を人の注意力ではなく機構で守る**（ADR 0012）。別 tx で outbox に書けると

    上限超過は削除せず `last_error` を残す（監視対象）
  - `Relay.Republish` — 送信済みを含めて期間指定で再送（再生の正は outbox。check #10 の下地）
  - `ddl/outbox.sql` / `ddl/inbox.sql` — テンプレート。物理テーブルはサービスごと（internal-05）
- `core/eventbus` — SNS FIFO 送信 / SQS FIFO 受信。`MessageGroupId`=集約ID、
  `MessageDeduplicationId`=イベントID。受信は raw message delivery 前提で envelope を直読み
- photo: `outbox` マイグレーション、`photo.published` / `photo.deleted` の発行

### check #8: relay 停止から回復する（実測）

| 確認 | 結果 |
|---|---|
| relay 停止中の公開が outbox に未送信として残る | ok |
| relay 起動後に `published_at` が入る（遅れて必ず届く） | ok |
| 受信側の inbox に記録される（バス経由で到達） | ok |

実 E2E（Keycloak + authz + photo + LocalStack + gear）でも確認した。alice が写真を
公開 → outbox 1行（未送信）→ relay 起動 → 1秒周期で送信 → gear consumer が受信 →
`inbox` に1行。`relay: 送信 count=1` と `consumer: 適用` がログに出る。

### check #9: inbox が重複配送を無害化する（実測）

同一イベントIDのメッセージを `MessageDeduplicationId` だけ変えて再投入した
（**バスの5分窓ではなく inbox が弾いていることを見るための手順**）。結果は
`重複イベントをスキップ` のログ1行、inbox は1行のまま、副作用なし。

重複を**エラーではなく applied=false** として返すのが要点。エラーにすると consumer が
メッセージを削除せず、同じものが永遠に再配信される（無害化ではなく無限ループになる）。

さらに `photo republish --since` で送信済みイベントを再送しても inbox は1行のまま
（再送も at-least-once の一形態であり、受信側の冪等性で吸収される）。

### 気づき

1. **sqlc はクエリを書いていないテーブルもモデルに出す。** outbox / inbox を足しただけで
   `sqlc diff` が落ちた。スキーマ全体から型を起こすため。生成物の再生成が必要で、
   これは「core 標準テーブルを各サービスが物理的に持つ」設計の副作用として毎回起きる
2. **photo の 500 応答も原因を捨てていた。** 4.1 の gear で直したのと同型の穴が
   `handler/external/v2` にもあった（`problem.CodeInternal` だけ返してログに何も残らない）。
   検証中に authz 停止に気づけず遠回りした。**外に出さない情報ほどログに落とす**
3. **コンテナを落とすと依存が芋づるで死ぬ。** `mise run migrate` の `db:up` が
   mysql コンテナの Recreate に失敗して停止し、authz（ホストプロセス）がそのまま死んだ。
   CI では `CI=1` で `db:up` を飛ばすが、ローカルでは「migrate したら別のものが止まる」が
   起きる。実行中のスタックがあるときは `CI=1` を付けて migrate する
4. **検査スクリプトは「何が担保するか」を分けて書く。** 同一 tx であることは単体テスト
   （ADR 0012 のガード）が、配送の回復は E2E スクリプトが担保する。スクリプト側で
   outbox に直接 INSERT しているのは前者を二重に検査しないため——**役割を書いておかないと
   「tx の検査をしていない」ように読める**
