## 2026-09-27 — ステージ 2.2 前半: API のバージョニング規則（ADR 0017、#45 / #16）

### 作ったもの

- `httpapi.API.AddMajor(n, version)`: 同じリスナー・同じルータにメジャー n の API を並行して作る。パスは `/v<n>` 配下、
  OpenAPI は別ドキュメント。スキーマの登録先をメジャーごとに分けていることをテストで検査
- `genapi`: メジャーごとに `<listener>.openapi.json` / `<listener>.v<n>.openapi.json` を出す。コードに無いメジャーのファイルが
  `api/` に残っていれば `-check` で落とす
- `api-breaking.sh` を規則の検査に作り替え、`api-breaking.test.sh` で違反を1件ずつ作って検査する（`mise run check` に含む）

### 実験（`api-breaking.test.sh`、10 シナリオ）

| シナリオ | 結果 | 理由 |
|---|---|---|
| 変更なし | 通る | |
| v1 への破壊的変更 | 落ちる | 既存のメジャーへの破壊的変更は通さない |
| **v1 への破壊的変更 + メジャーを 2 に上げる** | **落ちる** | ファイル名のメジャー 1 と食い違う（0.4 時点では通っていた） |
| v2 を並行提供（v1 は無変更） | 通る | |
| v2 のパスに `/v2` が無い | 落ちる | パスの接頭辞 |
| v2 のファイルに 3.0.0 | 落ちる | ファイル名とメジャーの食い違い |
| v2 を飛ばして v3 | 落ちる | 1つ前のメジャーが無い |
| v2 を足して v1 を消す（予告なし） | 落ちる | deprecated でない操作が残っている |
| deprecated 済みの v1 を消す | 通る | 廃止予告済み |
| `external.v1.openapi.json` という名前 | 落ちる | 名前の規則 |

### 気づき

1. 0.4 の `api-breaking.sh` は「破壊的変更ならメジャーを上げる」だけで、上げれば同じファイルを書き換えて旧版を消せた。
   並行提供を機械で強制するには、ファイル名とメジャーを結び、既存ファイルへの破壊的変更を一切通さない必要がある
2. huma の `Config` をコピーして2つ目の API を作ると、OpenAPI（スキーマの登録先）をポインタで共有し、v2 の型が v1 のスペックに混ざる。
   メジャーごとに設定を作り直す
3. テストの一時リポジトリでは mise の設定が無く `oasdiff` が起動せず、その失敗を「破壊的変更を検出」と取り違えていた。
   スクリプト本体も同じで、比較器が動かなくても「破壊的変更あり」と報告していた。先に `oasdiff` の起動を確かめて止める。
   テストは失敗の**理由**まで照合する（落ちるべきものが別の理由で落ちても通ってしまうため）
