## 2026-09-27 — ステージ 2.2 photo の v2 を並行提供する（ADR 0017、#45 / #16）

### 作ったもの

- `handler/external/v2`（パッケージ `externalv2`）: external リスナーのメジャー2のアダプタ。v1 の handler を複製し、
  **usecase は v1 と共有**。v1 からの変更は `POST /v2/photos` が 201 を返すことだけ（0.4 で「201 への移行は /v2 の題材にする」とした変更）
- `app.APIs` が同じ external リスナーに `ext.AddMajor(2, VersionV2)` で v2 を足す。`api/photo/external.v2.openapi.json` が生成される
- ルーティングの回帰テスト（`app/routing_test.go`）に `/v2` の5本を追加

### 実験

| 確認 | 結果 |
|---|---|
| `api:breaking`（base = main） | v1 は「破壊的変更なし」、v2 は「新しいメジャー 2（external.openapi.json と並行提供）」で通る |
| v2 のスペック | `info.version` 2.0.0、全パスが `/v2/`、`POST /v2/photos` の成功は 201 |
| v1 のスペック | 変更なし（`POST /photos` は 200 のまま） |
| 同じリスナーでの到達 | `/photos/...` と `/v2/photos/...` の両方にルータが振り分ける |

### 気づき

1. アダプタは v1 を**複製**した。v1 の型を v2 から参照すると、v1 に項目を足しただけで v2 の契約が黙って変わり、
   v1 の廃止も v2 の書き換えを伴う。複製にしておけば、廃止は `handler/external` と1ファイルの削除で済む
2. 利用側（frontend）はまだ v1 を使っている。移行は別 PR にする。並行提供中は v1 で動き続けるので急がない
