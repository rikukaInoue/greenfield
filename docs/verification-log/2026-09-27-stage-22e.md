## 2026-09-27 — ステージ 2.2 photo v1 を削除する（並行提供の手順の完了、#16 / #45）

### 作ったもの

- `handler/external`（v1 のアダプタ）を削除。usecase / domain は無変更（ADR 0017 の「廃止はアダプタ1つとスペック1ファイルの削除」）
- `genapi`: 上位のメジャーがあり自身の操作が0件のメジャーは廃止済みとして出力しない（`httpapi.New` はメジャー1の API を必ず作るため）。
  操作の無い骨格（gear）のメジャー1はこれまでどおり出す
- `dev/loadgen` を `/v2/photos` に移行
- `app/routing_test.go`: external のルート表から v1 を外し、v1 のパスに届かないことを固定

### 手順の全体（#16「/v2 並行提供の手順が回る」）

| 段階 | PR | `api:breaking` |
|---|---|---|
| 規則の導入 | #112 | — |
| v2 を並行提供（提供側） | #115 | v2「新しいメジャー 2（v1 と並行提供）」 |
| 利用側（frontend）を v2 へ | #116 | 対象外（frontend のみ） |
| v1 を deprecated（廃止予告） | #117 | 「破壊的変更なし」 |
| v1 を削除 | 本 PR | 「削除（base で全操作が deprecated。廃止予告済み）」 |

削除後の確認: E2E 10本、`loadgen`（30 リクエスト、エラー0: 一覧 200 ×24 / 投稿 201 ×6）、v1 の `GET /photos` は 404。

### 訂正

`2026-09-27-stage-22c.md` と `2026-09-27-stage-22d.md` の「リポジトリ内に v1 の利用者はいない」は誤り。
**`dev/loadgen`（1.5 のオンラインマイグレーション訓練で使う）が v1 の `/photos` を直接呼んでいた。** 削除の直前に
v1 のパスを grep して見つけ、本 PR で `/v2` へ移した。

### 気づき

1. 利用者の洗い出しを「frontend を移した」で済ませていた。API の利用者はアプリだけでなく、負荷ツールや
   訓練スクリプトなど開発用の道具にもいる。**削除の前に旧パスを grep する**手順を ADR 0017 の運用に足すべき
2. deprecated にした時点で loadgen が v1 を使っていても何も起きない（deprecated は非破壊）。気づけるのは削除の段階だけ。
   本番で同じことを防ぐには、deprecated な操作へのアクセスをログやメトリクスで数える必要がある（Phase 6 の観測項目）
3. 手元で allinone を直接起動すると、監査5（#113）の許可リストにより `ENV` 未設定で開発用の認証が起動を拒否する。
   `mise run` 経由なら `ENV` が入る。直接起動するなら `ENV=dev` を付ける
