計測コードは新モジュール `telemetry/`（core とは別 go.mod。理由は internal-06 §10.1）。

|---|---|

## 気づき

1. **photo の一覧(200)は業務 DB に触れないことがある**。alice が写真を持たない場合、
   ListAccessible（localauthz、別プール）で完結し観測対象のプールが動かない。
   「200 が返る負荷」と「観測対象に届く負荷」は別物 — メトリクスの検証は
   値が**動く**ところまで見る（0 のままは fail open と区別できない）
2. **`db_pool_max = 0`（無制限）**。photo / gear とも MaxOpenConnections 未設定で、
   「プール使用率」という概念がまだ成立しない。上限設定は挙動変更なので別 issue
3. **gear のデプロイイメージは #158 以降壊れていた**。gear の Dockerfile が
   photo-client（4.1 で追加された replace 依存）を COPY しておらず、
   誰もリビルドしなかったため潜伏。telemetry 追加のキャッシュ破りで露出（本 PR で修正）。
   platform/authz の Dockerfile（5.1）も同型で telemetry 分を修正
4. replace 忘れ・COPY 忘れを機械で止める検査は #163 に起票（fail open の5例目）

## SQL 由来 gauge の規約

「読めない」は **-1** を返す（0 と欠測を混同しない）。`telemetry.ObserveGauge` に記載。
