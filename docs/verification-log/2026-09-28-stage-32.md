### FGA 最小モデル（docs/03-platform.md のとおり）

viewer / editor は直接割り当てず `owner or operator from parent` で導出する。
オペレータの権限を専用機構なしで ReBAC に載せる検証（platform operator が parent 経由で
全 photo を見られる）を含む。

### 気づき

1. **OpenFGA のモデルは追記専用（immutable versions）。** 毎回 write すると起動のたびに
   版が増える。`EnsureModel` は最新版と意味比較（JSON 正規化して DeepEqual）し、
   差分があるときだけ書く。realm-as-code（keycloak 3.1）と同じ「同一なら書かない」設計
2. **tuples:write の自然冪等は read で絞ってから書くしかない。** OpenFGA は既存タプルの
   write / 不存在タプルの delete をエラーにする。サービス側で TupleExists で先に絞り、
   残りだけ書く。絞りと書きの間の競合に備えて1度だけやり直す。docs/03-platform.md が
   「API の性質として保証する」と定めた冪等を、この層で担保している（Eventual 化への備え）
3. **check #7 のテストは「新規に何件書いたか」で判定してはいけない。** 冪等 API なので
   再実行すると written=4 skipped=1 のように変わる。`written + skipped = 期待数`
   （＝呼び出し後に望みの状態か）で見る。最初 written=5 固定で書いて再実行で落ちた
4. **モデル比較で consistency をモックできない。** ユニットテストは fake FGA で
   マッピング・冪等・順序・バリデーションを確かめ、導出と consistency hint の実挙動は
   実 OpenFGA に対する authz-check.sh に委ねた。両方を CI で回す
