### 作ったもの

- **confidential client（Authorization Code + PKCE）**: `/auth/login` → Keycloak →
  `/auth/callback` で code をトークンへ交換（client_id=ssr + secret、S256、state / nonce）。
  依存ライブラリ無し——Go 側 oidcauthn と同じ判断で、issuer 固定・code フロー固定に
  絞れば discovery の fetch とフォーム POST だけで足り、ライブラリの暗黙の自由度ごと消せる。
  discovery の issuer 不一致は起動でなくログイン初回に落ちる（internal-07 の罠の検出）
- **トークンはサーバー側ストアへ**: `createFileSessionStorage` に移行し、Cookie が
  運ぶのは**ストアのセッションIDだけ**。以前は署名 Cookie にトークンが base64 で
  載っていた（httpOnly でも復号すれば見えた。stage-52 前半の気づき2の宿題）。
  devtoken ログインも同じストアを通る（経路で露出条件が変わらない）
- 期限切れは middleware が refresh token で取り直す（expirySlack 30秒。devtoken は対象外）。
  ログアウトは Keycloak の end_session まで倒す（id_token_hint + post_logout_redirect_uri）
- **loader 合成**: `packages/gear-api`（生成型）を追加。photos/new の loader が
  gear 一覧を引いて使用機材セレクタを出し、詳細の loader が photo と gear item を
  合成する（同じ trace / request-id で繋がる）。gear 側の欠落は本体を道連れにしない
  ——4.1 の作例併合（詳細ごと失敗）とは逆で、ここは表示の付加情報だから
- 4.4 の `gear_link_status` を投稿フォーム経由で通し、詳細に「紐付け確認中 / できませんでした」を表示

### 気づき

1. **Keycloak の `--import-realm` は既存 realm を上書きしない。** realm.json に
   redirect URI を足しても、ボリュームが残っているローカルでは反映されず
   `Invalid parameter: redirect_uri` になる。CI は毎回フレッシュなので realm.json が正。
   ローカルは admin API で合わせるか volume を作り直す（今回は前者）
2. **ログアウトの検証は「/login に戻る」ではなく「資格情報の再入力が要る」を見る。**
   OIDC 構成では /login が即 OP へ跳ぶため前者は観測できない。後者は
   「ローカルセッション破棄 + OP セッション終了」の両方が成立して初めて起きる
   （OP セッションが残っていれば SSO で自動ログインされ、フォームは出ない）
3. **post_logout_redirect_uri は登録制**（`post.logout.redirect.uris` 属性。`+` で
   redirect URIs と同じ集合を許可）。未登録だと確認画面で止まる
4. **E2E のポートは環境変数で逃がせるようにした。** ローカルの :8080 / :3000 が
   別プロジェクトに使われていると、webServer の health 検査が**他人のサーバーの 404**を
   見て新規起動→bind 失敗になる（「ポートが listen している ≠ 目的のプロセス」の変種）

### 残り

- ステップアップ（AAL2 / RFC 9470）の実フローは任意課題 #12（#57）のまま
- セッションストアはファイル（単一プロセス前提の検証ビルド）。複数インスタンスでは
  Redis / DB へ差し替える（session.ts の export だけ見ればよい形にしてある）
- Tier 2（コンテナ化 SSR + Caddy）での通しは 5.1 の器があるので必要になったら
