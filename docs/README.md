# Greenfield検証ビルド 設計書

プロダクション設計（マルチドメインAPIモノレポ + Yii段階移行）の**greenfield検証版**。移行を持たない新規プロダクトとして、Goバックエンドと認可基盤を個人のプライベート環境で実際に構築し、設計の主張を実証する。**位置づけは試作（prototype）**であり恒久運用を前提としない。検証の主役はCI/CDのサービス単位分離とフィーチャーフラグによるオンラインマイグレーションである（05-roadmap.md）。費用原則: Phase 0〜6は完全ローカル（クラウド費用ゼロ）、AWSはPhase 7のみ・短期間の使い捨て。

## プロダクション版との関係

コード規約・パターンは同一とし（`conventions/` に掃除済みコピー）、前提だけを差し替える。検証で得た修正・雛形はプロダクション版へ還流する。

| 項目 | プロダクション版 | 検証版（本書） |
|---|---|---|
| 既存システム移行 | 中核テーマ（Yii 2アプリ、複数年） | なし |
| 認証 | 外部の共用基盤（Kratos + Hydra） | Keycloak（セルフホスト1コンテナ、realm-as-code。ログインUI等は自作しない。ステップアップE2Eは任意課題） |
| 認可（authz / OpenFGA） | 外部の共用基盤 | **本リポジトリで自作**（03-platform.md） |
| IaC | platform運用（別管理） | 同一リポジトリ `infra/`（試作のため同居） |
| ネットワーク | TGWハブ&スポーク、ingress/egress VPC | docker compose（ローカル）+ 任意で単一VPC |
| 決済 | あり（AAL2 + introspection） | なし。危険操作サンプル（アカウント削除）でステップアップを検証 |
| フロントエンド | SSR別リポジトリ | 同リポジトリ `frontend/`（pnpm workspace、任意） |
| イベント基盤 | Outbox + SNS/SQS FIFO | 同一。ローカルはLocalStack |
| NFR | §11仮設定 | なし。検証チェックリスト（04）が成功条件 |
| 体制 | 複数チーム | 個人 |
